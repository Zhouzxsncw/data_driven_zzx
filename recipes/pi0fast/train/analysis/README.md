## Loss 语义与"00073 为什么比 00036 高"（2026-09-11 补充）

π0 FAST 的 loss 是 **FAST token 上的交叉熵**（pi0_fast.py compute_loss：对
tokenized_prompt 后缀做 next-token 预测，-Σ p·logp / mask 数），不是 MSE。随机初始化
的 loss=12.77 ≈ ln(262144)（PaliGemma 全词表均匀猜测），1.40 nats = 真 token 概率
24.7%（困惑度 4.06），0.19 nats = 82.7%（困惑度 1.21）。

00073 当前 1.40 vs 00036 最终 0.19 的三个原因（数据实测）：

1. **数据体量**：00073 有 194,273 帧 / 630 eps，是 00036（50,440 帧）的 3.85 倍；
   00073 每 epoch 需 6071 步（bs32），00036 只需 3153 步（bs16）。
2. **训练进度**：00073 才走 27%（lr 仍有 2.19e-5，88% 峰值）；00036 的 0.19 是
   走完 20000 步、lr 衰减到 2.6e-6 时的值，且它已把小数据集过了 **6.34 遍**
   （00073 全程也只过 4.94 遍）。
3. **按 epoch 对齐后 00073 反而更快**（同数据遍历次数下）：

| epoch | 00036 (step) | 00036 loss | 00073 (step) | 00073 loss |
|---|---|---|---|---|
| 0.5 | 1576 | 2.110 | 3035 | **1.975** |
| 1.0 | 3152 | 1.696 | 6071 | **1.631** |
| 1.3 | 4098 | 1.484 | 7892 | **1.420** |

00036 的 0.19 本质是 6.3 遍小数据集上的记忆级拟合；00073 数据更多样，最终 loss
预计落在更高位置（>0.19），这不是问题——跨数据集的 CE 不可比，真机评测才是判据。

另：00036 的 X-VLA run（`/home/xk/VLA/X-VLA/runnings/00036_tongbot/`）train.log 标量
loss 因 gripper 项 BCE 错配无界下探、不可作选点依据；其真实指标（TensorBoard
position_loss）最低 min 0.3896@29940，最终 ckpt-30000 即最优。
